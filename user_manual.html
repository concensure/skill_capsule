The Executable Skill Runtime

Skill Capsule is not just another documentation format. It is a portable, atomic, and executable runtime for AI coding workflows.

Deterministic

Ensures consistent, reproducible outcomes across diverse environments.

Atomic

Manages artifacts and state transitions as indivisible units.

Governed

Built-in audit logs and permission checks for enterprise-grade safety.

Why it exists

Traditional "Skill" documents are passive. They rely on the LLM to interpret instructions correctly. Skill Capsule takes the driver's seat, enforcing boundaries and performing pre-flight checks before any action is taken.

Passive Skill vs. Active Capsule

The fundamental shift from "What can I do?" to "How do I execute this safely?"

Feature Standard Skill (Passive) Skill Capsule (Active)
Execution LLM-driven (Best effort) Runtime-driven (Enforced)
Parameter Parsing Handled by LLM (Fuzzy) Structured & Validated
Tool Approval Implicit/Manual Explicit (Gated/Policy-driven)
Safety Narrative rules Hard-coded preflights & blocks
State Session-bound Persistent, atomic artifacts
Governance None (Implicit) Explicit audit logs & metrics
Dependencies Manual mention Automated resolution

Security & The Trust Model

Why "Shell-Free" and "Isolation" matter in your local IDE.

1. Injection Prevention

AI Agents can be "tricked" by prompt injections in untrusted code. Skill Capsule's Registry-Only model ensures that even if an AI is tricked, it can only run commands you've explicitly pre-approved.

2. Supply Chain Trust

When you download a capsule from the community, you don't need to audit every line. The Sandboxed Execution ensures the skill is a black box with restricted permissions (e.g., `read_only`), protecting your `.env` files and credentials.

3. Portability (Determinism)

Ensures "Works on My Machine" actually means "Works Everywhere." Docker-backed isolation guarantees that a skill runs in the exact environment required, preventing drift between VS Code and CI/CD.

4. No "Shell-Shock"

By using shell-free execution, we prevent "Space-in-Filename" bugs from becoming "Wipe-my-Drive" disasters. Arguments are passed directly to the OS, bypassing the dangerous shell interpretation layer.

The Core Pillars

Transparency

Every step—from classification to verification—is recorded as a JSON artifact. You can inspect the "lineage" of any task to see exactly which hooks were run and why.

Atomic Capsules

Capsules are bundles of "Atoms" (addressable capabilities). When a task is matched, only the necessary atoms are activated, keeping the context window clean and focused.

Guardrails

Built-in negative intent detection blocks dangerous operations (like `git push` when explicitly forbidden) before they ever reach the execution phase.

Workflow Mechanisms

The lifecycle of a Skill Capsule task follows a deterministic path:

graph LR A[Input Task] --> B(Classify) B --> C(Match Atoms) C --> D(Compose) D --> E(Prepare) E --> F(Activate) F --> G(Verify) G --> H[Outcome Recorded]

Artifact Lineage

Each run generates a unique `run_id`. All artifacts (Compose, Prepare, Verify) are linked together, allowing for partial resumes and deep forensics.

Architecture Deep-Dive

The engineering behind the runtime's reliability.

Artifact Indexing

The runtime maintains a lightweight index of every `compose`, `prepare`, and `verify` run. This allows downstream tools to query lineage, latest successes, and resume hints without scanning the entire disk.

S/O/X Render Model

To fit into tight token budgets, skills can be rendered at three levels:

  • S (Simple): Summary only.
  • O (Operational): Full parameters & hooks.
  • X (eXtended): Examples & deep documentation.

Environment Passthrough

Isolation doesn't mean "disconnected." The runtime uses an explicit Passthrough Allowlist. You choose exactly which host variables (like `PATH` or `GITHUB_TOKEN`) reach the hook process, ensuring zero-leakage by default.

The Hook System

Hooks are the "hands" of the capsule. They execute in defined phases with strict permissions.

Phases

  • before_render: Environment setup & discovery.
  • before_action: Pre-flight safety checks (e.g., secret scans).
  • summarise: Post-action analysis.
  • verify: Validating the outcome (e.g., typecheck).

Permissions

  • read_only: Informational (git status).
  • read_write: Metadata updates (logging).
  • restricted_exec: Sensitive actions (git push).

Sandboxed Execution

Skill Capsule enforces shell-free execution, registry-only commands, and optional Docker-backed isolation to ensure hooks can't escape their boundaries.

Command Center

The `skillcap` CLI is the primary interface for managing and executing capsules.

Common Commands

# Initialize a new project
skillcap init --project "My App"

# Compose a new task (matches atoms & plans hooks)
skillcap compose "Fix the type error in src/index.ts" --budget 800

# Prepare for execution (runs secret scans & preflights)
skillcap prepare code.verify.typecheck --task task.json

# Apply a validated patch
skillcap patch apply .skillcapsule/patches/pending/fix.json

# Record the final result
skillcap outcome record outcome.json

Building Your Registry

Learn how to define Atoms and package them into powerful Capsules.

1. Define an Atom

Create a JSON file in `.skillcapsule/atoms/`. Define triggers, risk levels, and associated hooks.

{
  "id": "my.code.lint",
  "name": "Auto-Linter",
  "triggers": ["lint", "fix", "style"],
  "hooks": ["hook.lint.run"]
}

2. Package a Capsule

In `.skillcapsule/capsules/`, group atoms into a workflow. Set a token budget to control context size.

{
  "id": "my.safe.workflow",
  "atoms": ["my.code.lint", "code.verify.typecheck"],
  "budget": 600
}

3. Registry Synchronization

After adding new files, always run skillcap index to rebuild the lookup tables and generate the CIF.

Design Best Practices

How to build robust, reusable Skill Capsules.

1. Atom Granularity

Keep atoms focused. Instead of code.test.and.lint, create two atoms: code.test and code.lint. This allows the runtime to mix-and-match them based on the task.

2. Risk-Aware Triggers

Use specific triggers for high-risk atoms. For example, don't trigger a git.push atom on the word "save"—require "push" or "publish" to prevent accidental activation.

3. Hook Idempotency

Ensure your hooks (especially verify and summarise) can be run multiple times without side effects. This is critical for the Resume and Retry mechanisms.

4. Budget Management

Always set a budget in your capsules. A well-designed capsule should provide maximum value in under 800 tokens to leave room for the AI's actual work.

Self-Evolution (CIF)

The Capsule Interop Framework (CIF) is the "DNA" of your skill registry.

What is CIF?

A compressed representation of all triggers, risks, and dependencies. It allows the LLM to understand the entire registry without reading hundreds of JSON files.

The Feedback Loop

By using outcome record, you provide data for the meta.evolution capsule. It analyzes failures and proposes Patches to improve triggers or tighten security.

CIF Strengths

  • Token Efficiency: Hundreds of skills summarized in a few hundred tokens.
  • Fast Matching: Deterministic regex-based keyword matching.
  • Structural Integrity: Ensures atoms and capsules are always in sync.

The Safety Net

Does Skill Capsule have an "Undo" button? Yes, but it's smarter.

Atomic Rollbacks

If the verify hook fails (e.g., tests break), the runtime can signal the editor to revert changes. Because every action is an Artifact, the "previous state" is always known.

Branching Artifacts

You can "Resume" from any point in the lineage. If a prepare step fails, you don't start over—you fix the environment and resume from that specific receipt.

Workflow Recommendation

For your VS Code workflow: Use "Inspect Mode" for risky changes. The capsule will pause after prepare, show you the pre-flight results (secret scans, impact analysis), and wait for your manual activate command.

Real-World Use Cases

Guarded Refactoring

Using the `code.safe.edit` capsule, the runtime automatically checks for public API breakages and runs related tests before allowing a refactor to be committed.

Safe Publish Flows

The `github.upload.safe` capsule ensures that no secrets are accidentally leaked and that a human-readable commit message is generated before any push occurs.

Self-Evolving Registries

The `meta.evolution` capsule monitors how skills are used and proposes "patches" to the registry, allowing the system to learn and optimize over time.
